Vox AI Relay Android help

This guide is written in simple English so a browser can translate it. Never translate commands, URLs, tokens, request IDs, or BCP-47 codes.

1. Prepare the Gateway server

On the computer running OpenClaw, open PowerShell (Windows) or Terminal (Linux/macOS).

openclaw onboard --install-daemon
openclaw gateway status

A healthy service reports Runtime: running and normally uses port 18789. If stopped:

openclaw gateway restart
openclaw gateway status --require-rpc

To make it reachable from a trusted local network:

openclaw config set gateway.bind lan
openclaw config set gateway.auth.mode token
openclaw doctor --generate-gateway-token
openclaw gateway restart

Read the token:

openclaw config get gateway.auth.token

The token is a secret. Do not publish it or include it in screenshots. Plain ws:// is unencrypted; prefer wss://, Tailscale or a VPN outside a controlled LAN.

Find the computer IP: Windows ipconfig, Linux hostname -I, macOS Wi-Fi ipconfig getifaddr en0. Enter for example ws://192.168.1.50:18789.

2. Approve the phone

  1. Tap Connect and keep the phone screen showing the Request ID.
  2. On the Gateway computer run:
    openclaw devices list
  3. Find the pending Android device with the same Request ID.
  4. Approve it, replacing the example with the real ID:
    openclaw devices approve abc123
    Do not type angle brackets.
  5. Return to the phone. It should reconnect; otherwise tap Connect once.

If no request appears, tap Connect again and immediately repeat openclaw devices list. A retry can create a newer Request ID.

Diagnostics:

openclaw gateway status --require-rpc
openclaw logs --follow
openclaw doctor

Stop log viewing with Ctrl+C.

3. Notification pairing — OpenClaw 2026.9.1

This is not messenger pairing. Commands such as openclaw pairing list telegram and a code sent in Telegram only authorize people to chat through that channel. The Android app receives notifications as a node.

  1. In the app open Settings → OpenClaw notifications, enable notifications, then tap Register notification capabilities again.
  2. On the server run:
    openclaw devices list
    If the phone is pending, copy its Request ID and run:
    openclaw devices approve REAL_REQUEST_ID
  3. Then check the separate node capability approval:
    openclaw nodes pending
  4. Find the same phone declaring notifications and system, then run:
    openclaw nodes approve REAL_REQUEST_ID
  5. Verify it:
    openclaw nodes status
openclaw nodes describe --node NODE_ID_OR_NAME
    The phone should be connected, and its description should include notification capability or the system.notify command.
  6. Send a test:
    openclaw nodes notify --node NODE_ID_OR_NAME --title "OpenClaw test" --body "Notifications work."

REAL_REQUEST_ID and NODE_ID_OR_NAME are placeholders for values printed by your server; do not type them literally. Pending requests may expire quickly. If both lists are empty, tap registration again in the app and immediately repeat both checks.

Notification diagnostics:

openclaw doctor
openclaw nodes status
openclaw nodes pending
openclaw logs --follow

Do not remove a paired device unless retrying registration and capability approval both fail.

4. Voice languages

  1. Select a language reported by the installed Android TTS engine, or enter a BCP-47 code.
  2. Tap Test voice.
  3. If unavailable, tap Install missing voice data and follow Android settings.
  4. Run Diagnostics to check TTS, STT and on-device recognition.
  5. Allow microphone permission on first use.

Installed languages depend on the phone, Android voice engine, downloaded models and sometimes network access.

5. BCP-47 language codes

Formats: language, language-REGION, or language-Script-REGION. Examples: pl-PL, en-US, sw-KE, zh-Hans-CN, zh-Hant-TW, ja-JP, ar-SA.

IANA Language Subtag Registry
Unicode CLDR locale data

A valid code does not guarantee that the installed TTS/STT service supports it. Use Test voice and Diagnostics.

6. Common errors

Server not reachable: verify IP, port, same network, firewall and gateway.bind.
Unauthorized: choose Token/Password correctly and enter the matching secret.
Pairing required: follow section 2.
Notification pairing required: complete both approvals in section 3; do not look for it in messenger settings.
TLS trust error: install a trusted certificate. Debug builds can temporarily allow an untrusted certificate only for a known test server.
