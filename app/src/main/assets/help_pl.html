Pomoc Vox AI Relay

Nie tłumacz komend, adresów, tokenów, identyfikatorów ani kodów BCP-47.

1. Przygotowanie serwera Gateway

Na komputerze z OpenClaw otwórz PowerShell (Windows) albo Terminal (Linux/macOS).

openclaw onboard --install-daemon
openclaw gateway status

Poprawnie działająca usługa pokazuje Runtime: running i zwykle port 18789. Jeśli jest zatrzymana:

openclaw gateway restart
openclaw gateway status --require-rpc

Udostępnienie w zaufanej sieci lokalnej:

openclaw config set gateway.bind lan
openclaw config set gateway.auth.mode token
openclaw doctor --generate-gateway-token
openclaw gateway restart

Odczyt tokenu:

openclaw config get gateway.auth.token

Token jest tajnym hasłem. Nie publikuj go i nie pokazuj na zrzutach. ws:// nie szyfruje transmisji; poza kontrolowaną siecią używaj wss://, Tailscale albo VPN.

Adres komputera: Windows ipconfig, Linux hostname -I, macOS Wi-Fi ipconfig getifaddr en0. Przykład w aplikacji: ws://192.168.1.50:18789.

2. Zatwierdzenie telefonu

  1. Naciśnij Połącz i pozostaw na telefonie ekran z Request ID.
  2. Na komputerze Gateway wykonaj:
    openclaw devices list
  3. Znajdź oczekujące urządzenie Android z tym samym Request ID.
  4. Zatwierdź je, wstawiając prawdziwy identyfikator:
    openclaw devices approve abc123
    Nie wpisuj znaków < i >.
  5. Wróć do telefonu. Jeśli nie połączy się automatycznie, naciśnij Połącz jeden raz.

Jeżeli nie ma prośby, naciśnij ponownie Połącz i od razu powtórz openclaw devices list. Ponowienie może utworzyć nowszy Request ID.

Diagnostyka:

openclaw gateway status --require-rpc
openclaw logs --follow
openclaw doctor

Podgląd logów zatrzymuje Ctrl+C.

3. Parowanie powiadomień — OpenClaw 2026.9.1

To nie jest parowanie komunikatora. Polecenia openclaw pairing list telegram i kod wysyłany w Telegramie służą wyłącznie do zezwalania nadawcom na rozmowę przez komunikator. Aplikacja Android odbiera powiadomienia jako węzeł.

  1. W aplikacji otwórz Ustawienia → Powiadomienia od OpenClaw, włącz powiadomienia i naciśnij Ponów rejestrację funkcji powiadomień.
  2. Na serwerze wykonaj:
    openclaw devices list
    Jeżeli telefon oczekuje na zatwierdzenie, skopiuj jego Request ID i wykonaj:
    openclaw devices approve PRAWDZIWY_REQUEST_ID
  3. Następnie sprawdź osobne zatwierdzenie funkcji węzła:
    openclaw nodes pending
  4. Znajdź ten sam telefon, zgłaszający funkcje notifications i system, po czym wykonaj:
    openclaw nodes approve PRAWDZIWY_REQUEST_ID
  5. Sprawdź wynik:
    openclaw nodes status
openclaw nodes describe --node ID_LUB_NAZWA
    Telefon powinien mieć stan connected, a opis powinien zawierać funkcję powiadomień lub polecenie system.notify.
  6. Wyślij próbę:
    openclaw nodes notify --node ID_LUB_NAZWA --title "Test OpenClaw" --body "Powiadomienie działa."

PRAWDZIWY_REQUEST_ID i ID_LUB_NAZWA są miejscami na wartości pokazane przez Twój serwer — nie wpisuj ich dosłownie. Prośby oczekujące mogą szybko wygasać. Jeżeli listy są puste, naciśnij ponowną rejestrację w aplikacji i od razu ponów oba sprawdzenia.

Diagnostyka powiadomień:

openclaw doctor
openclaw nodes status
openclaw nodes pending
openclaw logs --follow

Nie usuwaj sparowanego urządzenia, dopóki zwykłe ponowienie rejestracji i zatwierdzenie funkcji nie zawiodą.

4. Języki głosu

  1. Wybierz język zgłoszony przez silnik TTS Androida albo wpisz kod BCP-47.
  2. Naciśnij Test głosu.
  3. Jeśli głosu brakuje, wybierz Instaluj brakujące dane głosu.
  4. Uruchom Diagnostykę TTS, STT i rozpoznawania lokalnego.
  5. Przy pierwszym użyciu zezwól na mikrofon.

Dostępność zależy od telefonu, silnika głosu, pobranych modeli i czasem internetu.

5. Kody językowe BCP-47

Format: język, język-REGION albo język-PISMO-REGION. Przykłady: pl-PL, en-US, sw-KE, zh-Hans-CN, zh-Hant-TW, ja-JP, ar-SA.

Rejestr IANA Language Subtag Registry
Dane językowe Unicode CLDR

Poprawny kod nie gwarantuje obsługi przez zainstalowany TTS/STT. Użyj Testu głosu i Diagnostyki.

6. Typowe błędy

Serwer nie odpowiada: sprawdź IP, port, sieć, zaporę i gateway.bind.
Unauthorized: wybierz właściwy Token/Password i sekret.
Pairing required: wykonaj sekcję 2.
Powiadomienie wymaga parowania: wykonaj oba zatwierdzenia z sekcji 3; nie szukaj tej opcji w komunikatorze.
Błąd zaufania TLS: zainstaluj zaufany certyfikat. Wersja debug pozwala czasowo użyć niezaufanego tylko ze znanym serwerem testowym.
